# Mockup brief — "Bonafarm voer app" statistiek (new version)

Context: a Dutch petting zoo (kinderboerderij). Volunteers log animal feed with a phone app: bags (zakken) and bales (balen hooi/stro) in storage barrels ("Ton blauw" etc.), stables (stallen) and dispensers ("kokers": feed poured in, then consumed). Goal of the new app: order more efficiently. These are static HTML mockups of the STATISTIEK / BESTELLEN screens, with REAL numbers from 4 years of production data. All UI text in Dutch. Units: "zakken" for bagged feed, "balen" for hooi/stro. Never "kg".

Files (all in this dir): base.css (tokens + components), charts.js (window.barChart/lineChart/sparkline/heatStrip/gauge), example.html (pattern to copy), render.sh. Data (read-only) in ../analysis/summary.json (perFeed, perShute, perStable, overview, dataQuality — see keys below), ../analysis/advice.json (order advice per feed: status critical|warning|unknown|ok|overstock|inactive, orderQty, ratePerWeek, coverDays, dueInDays, lastDelivery, medianDeliveryIntervalDays, medianDeliverySize, consumedLast12m, isKoker), ../data/items.json (current stock per storage/feed), ../data/storages.json, ../data/feeds.json, ../analysis/findings.md (read this first, 60 lines).

How to build a page: write `build-<page>.mjs` (Node 24 ESM, no packages) that reads the JSON and writes `<page>.html` next to it, so every number on the page is real and reproducible. Then `./render.sh <page>.html [mobileH] [desktopH]`, then LOOK at both PNGs in out/ with the Read tool and fix overflow, overlaps, unreadable labels. Pick viewport heights so no content is cut off and little blank space remains.

Layout: mobile-first. Mobile = `.phone` frame 390px, app bar, content cards, bottom nav (Home, Voorraad, Statistiek, Bestellen; highlight the active tab). Desktop = `.desktop` frame 1280px with a left sidebar nav (same 4 items) and a 2 or 3 column card grid; same cards, more side by side. Both renders come from the same HTML: use a media query (max-width 600px → phone layout, else desktop layout) OR build two HTML files; whichever is simpler and robust.

Design rules (from the dataviz skill at /tmp/claude-1000/bundled-skills/2.1.292/e33f028fd2bc5ea21b340205af3a1f51/dataviz/ — read SKILL.md, references/choosing-a-form.md, references/anti-patterns.md): a headline number is a stat tile, not a chart; one axis per chart; bars thin with rounded ends; series colours only on marks, all text in ink tokens; status colours (good/warning/serious/critical) ONLY in status chips and always with an icon glyph + text; categorical hues from --cat-1.. in fixed order; sequential (--seq-*) for magnitude; legend for >=2 series; selective direct labels (not a number on every bar; last bar / max is fine); no rainbow, no pie charts, no dual axis. Round numbers for humans (halve zakken ok: "2,5"). Dutch number format (comma decimal). Dates like "do 2 okt". Every chart card has a title (what) and a one-line subtitle (unit/period). Each page should answer a concrete ordering question in its title/subtitle.

Status chip glyphs: ✓ Op voorraad (good), ▲ Bijna op (warning), ✕ Bestellen (critical), ? Telling onbekend (muted/neutral, for `unknown`), ≡ Te veel (serious, for overstock). "unknown" means: feed is in use but counted stock is 0 — bags go straight into the koker or nobody updated the count. Say that honestly in the UI ("niet geteld").

Reference date is 6 okt 2026 ("vandaag"). Keep each page ≤ ~7 cards on mobile. Prefer insight over decoration. Report back in ≤150 words: files written, PNG paths, anything you could not do.
